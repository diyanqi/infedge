# 用户套餐、资源隔离与流量配额设计

## 目标

OpenFlare 控制面支持普通用户购买套餐并管理自己的 CDN 资源。管理员维护套餐、支付渠道、节点和节点组；普通用户只能访问自己创建的 Zone、源站、代理规则和发布记录，Pages 项目当前仍由管理员管理。

## 套餐与支付

`of_subscription_plans` 保存套餐规则：月费、高速流量、超额限速、每日发布次数以及资源数量上限。用户购买成功后生成 `of_user_subscriptions`，同一时间只允许一条有效订阅。

易支付渠道保存网关地址、商户号和签名密钥。创建订单时根据渠道生成标准 `submit.php` 参数，异步通知通过 `notify_url` 校验签名并幂等更新订单和订阅；支付密钥只在服务端使用。

## 资源归属与权益

核心用户资源表增加 `owner_id`。管理员请求不受归属过滤；普通用户请求必须在 repository 查询中带 `owner_id`，不存在的资源统一表现为 404。用户写入资源前校验当前套餐的资源数量上限，发布时使用数据库日计数器原子预占并在发布失败时释放，保证并发请求不能绕过每日发布次数限制。

普通用户允许创建 Zone、域名、源站和代理规则，并可查看和操作自己的资源；Pages 项目的 owner 链路仍待单独完成，当前继续由管理员管理。全站配置发布仍然生成一个全局版本，但发布权限、次数和审计归属按用户校验。

## 节点与节点组配额

节点可属于一个节点组。节点组的月流量限制是组内节点共享的总额度；未分组节点使用自身月流量限制。访问日志在 OpenResty 侧按域名映射到资源 owner，Server 按自然月累计用户已提供字节，并在 Agent 心跳中同时下发节点/节点组全局额度和每个有效用户的套餐额度。用户套餐的超额速率按在线节点数分摊到各节点，并由 Agent 共享字典按 owner 分摊到并发请求；节点组额度仍按组内所有用户和节点的总流量计算。

## 兼容性与安全

旧资源迁移为管理员所有（`owner_id=0`），现有管理员控制台行为保持不变。节点协议新增字段使用可选 JSON 字段，旧 agent 忽略未知字段；新 agent 在未收到策略时保持原有行为。
